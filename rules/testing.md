# Testing

Use test-driven development by default: fail, pass, then refactor.
Cover behavior changes and bugs through observable outcomes, not private implementation details.
Write readable tests that show human intent through scenario, action, and outcome.
Keep tests independent; share setup only when it improves clarity.
Follow the existing test organization and ecosystem.
Never delete or weaken other tests merely to make a change pass.
Ask the user to decide when expectations conflict.
If meaningful automation is not possible, agree on alternative evidence with the user.
