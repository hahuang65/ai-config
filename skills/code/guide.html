01 · Inputs and authorization

Approved intent drives the work

Read canonical tasks.html, linked specs.html, approved mockups.html when present, applicable context files, and relevant ADRs.

Invocation is standing authorization. Routine reads, writes, test cycles, verification, documented service startup, and toolchain bootstrap proceed without repeated approval.

Stop for a slice that cannot be implemented as written, a destructive operation outside session-owned artifacts, or a genuine architectural fork with no signal in approved intent or the codebase.

02 · Test quality

Test behavior through stable interfaces

Prefer

  • User-visible behavior.
  • The highest stable public interface.
  • Real end-to-end code paths.
  • Tests that survive internal refactors.

Avoid

  • Private methods and internal collaborators.
  • Side-channel verification.
  • Signature or data-shape tests without behavior.
  • Batched tests for imagined implementation.
03 · Per-slice loop

One test, one implementation

  1. Use the slice Test surface and Spec Testing Decisions to confirm the public interface.
  2. Run the tdd-guide agent for the slice.
  3. Write one tracer-bullet test and confirm RED for the correct reason.
  4. Write minimum implementation and confirm GREEN.
  5. Repeat one criterion at a time.
  6. Refactor only while GREEN and rerun tests after each step.
  7. Mark criterion and slice visible status plus data-status complete in tasks.html.
RED→GREEN: test 1 → implementation 1
RED→GREEN: test 2 → implementation 2
REFACTOR only while GREEN
04 · Intent changes

Keep canonical UI synchronized

Material UI redesign: stop the affected slice, update mockups.html through review-artifact, synchronize specs.html and tasks.html, renew invalidated approvals, then resume only after intent is synchronized.

Terse corrections can proceed directly only when they stay within approved UI intent.

05 · Completion

Verify, then clean

  1. Run type check, lint, the full test suite, and build. Fix failures until all pass.
  2. Run the refactorer agent in hygiene mode on changed files. Apply SAFE cleanup and report higher-risk candidates.
  3. Rerun full verification after any hygiene edit.
  4. Report every final command, scope, and outcome.

Inside build: proceed directly to Review change. Standalone: offer optional refactor and review-code next steps.

06 · Git boundary

Leave delivery to the user

No staging, commit, push, or delivery occurs in code.
