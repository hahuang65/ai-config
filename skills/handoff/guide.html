Session routing

/handoff

Write a focused routing slip so another agent session can continue one concern without inheriting the full conversation.

01 · When to use

Split concerns, not context windows

Side task

Preserve the current session's focus while another session handles an out-of-scope concern.

Prototype

Move a focused experiment into its own disposable context.

Harness transfer

Move work between Claude Code, pi, or another agent session.

Selective continuation

Give a fresh session only the brief and sources it needs.

/compact summarizes a conversation. /handoff selectively starts an independent one.

02 · Location

Literal /tmp/ only

Write /tmp/handoff-<short-slug>-<YYYYMMDD-HHMM>.md. Do not use $TMPDIR or another shell variable; literal paths avoid expansion-related safety prompts.

The file is disposable, never belongs in the workspace, and must not be committed.

03 · Content

Keep the routing slip short

  1. Purpose: what the next session must accomplish.
  2. Relevant context: only facts that are not already in durable sources.
  3. Suggested skills: the best workflow entry points.
  4. Pointers: canonical specs, tasks, ADRs, commits, diffs, and external URLs.
# Handoff: <purpose>
## Purpose of the next session
## Relevant context from this session
## Suggested skills
## Pointers (not duplicated content)
04 · Rules

Reference; do not copy

  • Link to durable sources instead of reproducing them.
  • Shape the document around the user's handoff brief.
  • Redact credentials, tokens, passwords, and personal data.
  • Suggest relevant skills explicitly.
  • Tell the user the absolute output path.
05 · Continue elsewhere

Resume with /pickup

In a fresh session, run /pickup with no argument to select the most recent handoff, or pass a slug or topic to select a specific file.

Do not continue the handed-off task here. Report the path and one-line next-session purpose, then return to the original focus.
