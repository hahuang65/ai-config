/handoff

Compact the current conversation into a handoff document so a fresh agent session can pick up the work. Output is disposable — written to the OS temp directory, not the workspace.

01When to Use

Out-of-scope discovery

You're in a /grill session and a separate concern surfaces. Hand it off so the current session stays focused, and the new session can pick up the diversion when it's ready.

Prototype split

The current session has heavy domain context. A prototype belongs in its own scratch space. Handoff the prototype question so the current session's context stays clean.

Tool-to-tool transfer

Work needs to move between AI coding tools (e.g. Claude Code → oh-my-pi). The handoff doc is the routing slip.

Session hygiene

You want the current session pure and focused on one job. Park the side concern elsewhere.

02Where the Doc Lives
OS temp directory only. Resolved from $TMPDIR, falling back to /tmp on Unix or %TEMP% on Windows. Never the workspace, never committed.

Filename pattern: handoff-<short-slug>-<YYYYMMDD-HHMM>.md. The user gets the absolute path to pass to the next session.

03Document Structure
# Handoff: <one-line purpose> ## Purpose of the next session <2-3 sentences. What is the next session being spun up to do?> ## Relevant context from this session <Only what the next session needs to know. Do NOT duplicate content from PRDs, plans, ADRs, issues, commits, or diffs. Reference them by path or URL instead.> ## Suggested skills - /grill — to refine domain terminology around X before drafting - /prd — once the design is settled - /implement — once tasks are approved ## Pointers (not duplicated content) - PRD: docs/features/<slug>/prd.md - Tasks: docs/features/<slug>/tasks.md - ADRs touched: docs/adr/0007-... - Recent diff: git log -p <sha>..<sha> - External: <URLs>
04Rules
RuleWhy
Reference, don't duplicateIf a PRD says X, link to the PRD. The handoff is a routing slip, not a copy. Copies rot.
Tailor to the briefIf $ARGUMENTS is provided, shape the doc to that purpose. Skip context the next session won't need.
Redact sensitive contentAPI keys, passwords, tokens, PII. Even in temp dir, the file is plaintext on disk.
Suggest skills explicitlyThe next agent reads cold. Naming skills (/grill, /prd, /tasks, /prototype, etc.) lets it spin up directly.
DisposableDon't commit it. Anything worth keeping belongs in a PRD, ADR, or commit message.

06After Writing
Do NOT continue work on the handed-off task in the current session. That defeats the purpose of the split. Tell the user the path, then return to the original focus.
