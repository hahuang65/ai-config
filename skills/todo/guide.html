01 · Slice shape

Vertical, never horizontal

Vertical slice

“Customer can place an Order and see it in order history.”

  • Crosses every required layer.
  • Proves one complete path.
  • Can be demonstrated alone.

Rejected horizontal slice

“Set up the Order schema.”

  • Touches one layer only.
  • Leaves no visible complete behavior.
  • Must be reframed or combined.

Prefer many thin slices. If a slice is large, split it without breaking end-to-end value.

02 · Execution mode

Prefer unattended work

ModeUse
AFKCan run without human interaction. Prefer this for most slices.
HITLNeeds real human judgment, such as a design or architecture decision.
03 · Canonical artifact

Write structured tasks.html

  • Link visibly to the source specs.html.
  • Set document-level artifact kind and version attributes.
  • Give each slice stable identity, status, dependencies, mode, and story metadata.
  • Show its public Test surface and acceptance criteria as visible content.
  • Give every criterion stable identity and status metadata.

Do not include file paths or code snippets in task bodies. The Test surface names a stable public interface or observable behavior.

04 · Process

Ground, draft, review

Standalone input can be a Spec path, Feature slug, or GitHub issue. When an issue is supplied, its body replaces specs.html as the task source.

  1. Read approved specs.html, approved mockups.html when present, selected context documentation, decision records, and relevant code.
  2. Draft slices in dependency order and carry forward user-story coverage and public test surfaces.
  3. Write canonical tasks.html with the title <feature title> - Tasks.
  4. Review granularity, dependencies, AFK/HITL mode, and story coverage through review-artifact.
  5. Apply feedback to the same live file until explicit approval.
05 · UI intent changes

Return to the approved design

  1. If Task feedback materially redesigns UI, pause the current Tasks approval review.
  2. Run the changed mockups.html through mockup and review-artifact until explicit approval.
  3. Then synchronize specs.html and tasks.html, renew the invalidated Spec approval, and renew the invalidated Tasks approval.
  4. Continue to implementation only after both approvals are explicitly renewed.
06 · Completion

Choose the implementation owner

Approval clears Tasks→Implement. Report the slice and mode counts, then choose code for AI implementation or coach for user implementation.

Ending review is not approval.
