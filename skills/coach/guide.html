/coach

Vertical-slice TDD where the user writes the code. AI reads approved mockups.html when present as Authoritative intent, writes ONE failing test, waits, verifies, then writes the next. No batched tests and no AI-authored implementation during the coaching loop.

02Hard Rules

Do

  • Write ONE failing test at a time
  • Show the user the expected public interface from the spec/task test surface up front
  • Run the test before claiming RED to confirm it fails for the right reason
  • When the user signals they're ready (any wording, not a keyword), run only the relevant test
  • Use the ubiquitous language from the applicable context files in test names
  • Refactor together when GREEN; suggest, let the user execute

Don't

  • Write all tests upfront — that's the rejected horizontal pattern
  • Write the implementation code during the coaching loop
  • Preview the next test to the user — they should implement against the current one without anticipating
  • Refactor while RED
  • Patch a bad approach when the user reverts — start fresh
  • Run git commit — ever
03Why No Batched Tests
The horizontal anti-pattern: "Write all the tests upfront, then walk the user through each module." This produces crap tests.
  • Tests written in bulk test imagined behavior, not actual behavior
  • They check the shape of things (signatures, data structures) rather than user-facing behavior
  • They become insensitive to real changes — pass when behavior breaks, fail when it doesn't
  • The user outruns their headlights, committing to test structure before understanding the implementation

By writing one test at a time, each test responds to what was learned from the previous cycle. The test you write next is the test you now know you need.
