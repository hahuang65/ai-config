omp Hooks Migration — Diff Review

Working tree against main — 8 modified files (+153 / −131), 11 net-new files (5 hooks, 1 ADR, hooks README, 4 docs/claude artifacts), and 4 deleted TTSR rules. Architecture shift: "8 TTSR rules + 0 hooks" becomes "8 TTSR + 5 hooks". Pipeline 403/0, self-test 14/14.

Executive summary

Structured input parsing replaces stream regex where regex was losing.

What changed and why

TTSR — omp's time-traveling stream rule mechanism — is a markdown-frontmatter regex matched against the model's outgoing token stream. Living with the TTSR-only safety stack from the prior integration cycle revealed documented bypasses no markdown regex can fix: bash <(curl URL) slips past no-curl-pipe-interpreter, find / -delete slips past no-rm-rf-root, prose mentions of ~/.aws/credentials over-fire no-credentials-read, and bash <(sudo …) slips past any \bsudo\b regex.

This change migrates those 4 rules to omp pre-hooks — TS modules subscribed to tool_call events with structured input parsing — and adds 1 net-new post-hook (redact-keys) that mutates tool_result content to strip secrets. Output mutation is hook-only territory; TTSR fundamentally cannot do it. ADR-0006 codifies the new hook-vs-TTSR decision tree and supersedes the third pillar of ADR-0004.

Conservative scope: 4 of 12 bash-bound TTSR rules migrate. The other 8 (security, git-workflow, no-cloud-destroy, no-shell-write, no-deploy, no-db-mutation, no-dd-disk, no-broad-chmod) stay as TTSR — their regex has no realistic bypass and the markdown-authoring UX is preferable. Zero changes to Claude Code's safety stack: per-pattern denylist and curl shell hook unchanged, no regression.

Architecture shift

One safety layer becomes two, with a decision tree

The hook layer doesn't replace TTSR — it sits alongside it, with a clean delineation of which mechanism handles which pattern class. ADR-0006 documents the decision tree: input-bound patterns with bypass risk live as hooks; content-based patterns and simple bash regex without realistic bypass stay as TTSR; output mutation is hook-only.

Major comparisons

Three areas reshape

Safety stack — 12 TTSR + 0 hooks → 8 TTSR + 5 hooks

Before · TTSR-only
After · TTSR + hooks (per ADR-0006)

12 TTSR rules carrying the entire per-pattern enforcement load on omp. Markdown frontmatter condition: regex matched against stream text. Per ADR-0004 pillar 3, "no hook port — TTSR covers the same surface."

Bypasses surfaced in live use:

  • bash <(curl URL) — process substitution wraps the curl, regex sees no pipe
  • find / -delete — different command shape than rm -rf /
  • Prose mention of ~/.aws/credentials in a Write/Edit payload — over-fired the regex on commentary, not actual reads
  • bash <(sudo …) — same proc-subst bypass

And one capability gap with no TTSR workaround: redacting secrets that leak in tool output. TTSR fundamentally cannot mutate tool_result content.

8 TTSR rules + 5 omp hooks. Hooks own input-bound patterns with known bypasses + all output mutation; TTSR owns content-based and simple-bash-regex patterns.

Pre-hooks (4 · block tool_call before execution):

  • guard-rm.ts — tokenize+recurse, blocks broad rm -rf and find … -delete / -exec rm
  • guard-curl-pipe.ts — splits on pipes, blocks curl|*|bash and bash <(curl)
  • guard-credentials.ts — per-tool input check on read/edit paths + bash command parsing
  • guard-sudo.ts — \bsudo\s on bash input (consistency with other guards; the TTSR rule already had scope: tool:bash so there was no prose-overfire bug)

Post-hook (1 · mutate tool_result):

  • redact-keys.ts — multi-pattern redaction across read/edit/bash output with placeholder-skip allowlist

8 TTSR rules retained verbatim; development-workflow.md stays deleted from the prior cycle.

Code review · post-implementation triage

Good · Bad · Ugly · Questions

Post-implementation review caught a clutch of HIGH and MEDIUM items in the structured parsers and the redactor — all fixed in the verification chain before this diff-review was generated. The thoroughness of that pass is itself a data point on the migration's quality.

Good

  • Structured argv parsing depth. guard-rm, guard-curl-pipe, guard-credentials all hand-roll quote-aware tokenizers, paren-aware pipe splitters, env-var-prefix skippers, and recursive substitution walkers — exactly the parsing TTSR's stream regex couldn't do. The implementations stay readable because each helper is single-purpose (tokenize, splitOnPipe, splitOnSeparators, leadingWord, extractSubstitutions).
  • Per-tool dispatch in guard-credentials. read/edit check event.input.path directly with zero prose surface, completely eliminating the over-fire-on-commentary bug from the deleted TTSR rule. bash gets a separate, deeper code path.
  • redact-keys placeholder allowlist is well-targeted. Covers xxx-containing, your-/your_-prefixed, <…>, ..., all-same-char, "redacted" (already-redacted), and the 8-char minimum length. Docs and test fixtures pass through unmolested — exactly the right calibration for an output mutator.
  • Hook API contract verified against source. omp/hooks/README.md cites shared-events.ts:265 for the "no {allow: true}" invariant — the doc didn't guess at the API surface. That's the same posture as the earlier "{block, reason} only" decision documented in the extensions README.
  • Slice 5 implementation note is honest. guard-sudo.ts header comment explicitly states the migration is for consistency with the other guards, not to fix a specific bypass — the prior TTSR rule already had scope: tool:bash. Documenting the trade-off in-place keeps future readers from assuming there was a security reason.
  • Pipeline check enforces start-of-line export. test_omp_hook_shape uses ^[[:space:]]*export[[:space:]]+default[[:space:]]+function rather than just grepping for the words — a comment mentioning "export default function" doesn't satisfy omp's loader, and the check correctly insists on the signature shape, not the phrase.

Bad · all addressed pre-review

  • HIGH — fixed. guard-rm originally listed . and .. as broad targets — over-fired on the common, safe pattern find . -name "*.pyc" -delete. Both removed; comment in BROAD_TARGETS documents the omission.
  • HIGH — fixed. guard-rm missed ${HOME}, ~/, $HOME/, ${HOME}/ (trailing-slash variants of broad targets). Added; isBroadTarget() also normalizes trailing slashes generally.
  • HIGH — fixed. guard-curl-pipe's env-var-prefix skip was case-sensitive — missed http_proxy=… and other lowercase HTTP-proxy vars (valid bash, commonly used). leadingWord() now uses [A-Za-z_][A-Za-z0-9_]*.
  • HIGH — fixed. guard-curl-pipe's pipe splitter didn't handle |& (bash's stdout+stderr pipe) — would treat curl URL |& bash as one segment. Now consumes the & after the | at the split point.
  • HIGH — fixed. redact-keys originally only handled read + bash — edit wasn't in REDACT_TOOLS. But edit echoes file content in its result the same way read does, so secrets would leak through edit's response. Added.
  • MEDIUM — fixed. redact-keys's GitHub token pattern only matched the classic ghp_/gho_/ghu_/ghs_/ghr_ format. Added github_pat_[A-Za-z0-9_]{82,} for fine-grained PATs (introduced 2022).
  • MEDIUM — fixed. guard-credentials's .secrets regex was loose — over-broad. Tightened to /\.secrets([./]|$)/ to match .secrets.foo, .secrets/foo, or end-of-string but not arbitrary substrings.

Ugly · accepted trade-offs

  • Hooks are omp-only. Per ADR-0006, hooks run only on omp's TS-module hook system — Claude users continue to rely on the per-pattern denylist + curl shell hook, OpenCode has no hook surface at all. The 5 new hooks don't reach Claude users. Accepted: the migrated TTSR rules were also omp-effective only (Claude's regex pre-existed in claude/settings.json; OpenCode doesn't load rules), so no net loss of Claude/OpenCode coverage.
  • Hook reasons are shorter than the deleted rule bodies. The TTSR rules had multi-paragraph "right approach" guidance; the hook reason string is one line citing the blocked command snippet. More targeted but less educational. The model still has rule bodies for the 8 remaining TTSR rules, so the loss is bounded.
  • Live hook firing not stress-tested in a real omp session. Each hook is verified by code review + the pipeline shape check; no live omp tool_call was reproduced through each guard. Recommend a 3-pattern spot-check (find / -delete, bash <(curl URL), cat ~/.aws/credentials) before treating the hook layer as a hardened safety mechanism.
  • Hand-rolled bash tokenizers in three files. guard-rm, guard-curl-pipe, guard-credentials each carry their own quote-aware tokenizer / substitution-extractor with similar shapes. Pulling them into a shared omp/hooks/_lib/ module would reduce duplication but creates a coupling that has to be installed (more symlinks, more pipeline checks). Accepted as DRY-vs-isolation: each hook is independently auditable today.
  • guard-sudo migration is consistency-driven, not bypass-driven. Slice 5 explicitly acknowledges the prior TTSR rule wasn't actually broken (scope:tool:bash already prevented prose overfire). Migrating it anyway keeps the "all rm/curl/cred/sudo guards live in omp/hooks/pre/" mental model clean — but it's a UX choice, not a security fix. Documented in the header comment so future readers don't assume otherwise.

Questions for review

  • Should redact-keys also redact in the fetch tool's output? Currently REDACT_TOOLS deliberately omits fetch — fetch responses are typically API JSON the model needs to reason about, and redacting could break legitimate API key inspection workflows. But fetch can also return HTML pages that embed credentials. Worth a decision before the next hooks pass.
  • Live tuning will surface more bypass cases. The 4 hooks ship with the bypasses we currently know about — process substitution, find-exec, env-var prefixes, lowercase HTTP proxies. A week of live use will likely surface more (e.g., $()-eval, complex heredocs, base64-encoded commands fed to eval). Worth a follow-up backlog item?
  • Should the reason strings be longer? The deleted rule bodies had explicit "right approach" guidance — currently the hook just cites the blocked command. A medium-length reason ("blocked because X; do Y instead") would restore some of the educational UX.
  • Should the placeholder-skip allowlist in redact-keys be configurable? Project-specific fixture conventions (e.g., a project uses test_ prefixes) might want to extend it. Today it's a hard-coded function — fine for v1, worth revisiting if false positives appear.
Decision log · 1 new ADR + 4 design calls

Why we did what we did

ADR-0006 is the headline. The other four cards capture decisions discussed explicitly during slicing — they're not separate ADRs but they are load-bearing design choices that future readers will want to see captured.

ADR-0006 · new

Hooks replace TTSR for input-bound patterns with known regex bypasses

Codifies the hook-vs-TTSR decision tree. Hooks own input-bound patterns where structured parsing catches what regex can't, plus all output mutation. TTSR keeps content-based patterns (Write/Edit payloads) and simple bash regex with no realistic bypass. Supersedes ADR-0004's third pillar; pillars 1 + 2 of ADR-0004 remain in force.

HIGH · discussed
DESIGN CALL · scope

Hook-only on omp (Claude unchanged)

The 5 hooks are omp-only — Claude's per-pattern denylist + scripts/hooks/deny-curl-to-interpreter.sh were not touched. Per ADR-0006: the dangerous patterns the deleted TTSR rules covered are still blocked on Claude by the existing denylist + curl hook, none of which regressed. OpenCode was never affected by rules. Net Claude/OpenCode regression: zero.

HIGH · ADR-0006
DESIGN CALL · scope

Conservative migration — 4 of 12, not all 12

Hook-first-for-all was explicitly rejected in ADR-0006. The 8 remaining TTSR rules (security, git-workflow, no-cloud-destroy, no-shell-write, no-deploy, no-db-mutation, no-dd-disk, no-broad-chmod) have working regex with no realistic bypass. Migrating them buys nothing and trades markdown-authoring UX for TypeScript. Scope discipline is the win.

HIGH · ADR-0006
DESIGN CALL · convention

guard-* / redact-* naming, enforced by pipeline

pre/guard-*.ts for blockers; post/redact-*.ts for mutators. Enforced by test_omp_hook_shape per directory. Naming maps to the API contract: guards return {block, reason}; redactors return {content, details, isError}. Future hooks must follow the convention or fail the pipeline.

HIGH · documented in omp/hooks/README.md
DESIGN CALL · implementation

Structured argv parsing over regex

Every pre-hook (except the deliberately-simple guard-sudo) hand-rolls a quote-aware tokenizer + paren-aware splitter + substitution-recursor. Regex is a poor fit for tokenizing shell — it can't handle nesting. The 3 tokenizer copies are accepted DRY-vs-isolation trade-offs to keep each hook independently auditable.

HIGH · implementation pattern
DESIGN CALL · API surface

No {allow: true}, only {block: …}

omp's hook API supports {block: true, reason} but does not support {allow: true} to short-circuit approval prompts. Verified against shared-events.ts:265 and documented in omp/hooks/README.md. This means hooks can refuse but can't pre-approve — so "smart prompt suppressor" extensions remain infeasible. Accepted constraint.

HIGH · verified against source
Re-entry context · note from present-you to future-you

What to remember in two weeks

Key invariants

  • Hook API is {block, reason} only. There is no {allow: true} escape hatch — verified against shared-events.ts:265. Hooks can refuse but can't pre-approve. Don't design a "smart prompt suppressor" hook; it can't exist on the current API.
  • REDACT_TOOLS deliberately omits fetch. Fetch responses are typically API JSON the model needs to reason about. Redacting could break legitimate API key inspection. Currently: {read, edit, bash} only. Revisit if a real leak through fetch is observed.
  • . and .. are deliberately not in BROAD_TARGETS. find . -name "*.pyc" -delete is a common safe cleanup. The over-fire was loud enough during review to remove these from the broad-target set. If you add them back, expect to break Python projects' pre-commit hooks.
  • The 4 migrated rules' regex-bypass test cases live in their hook header comments. guard-curl-pipe.ts lines 4–11 enumerate the 4 bypass shapes. Don't refactor the comments away; they're the historical record of why each hook is shaped the way it is.
  • omp/hooks/ README.md is skipped by the install loop via [ -f "$hook" ] || continue + the glob being *.ts/*.js only. Don't add a *.md include or omp's loader will choke trying to import markdown.

Non-obvious coupling

  • ADR-0004 + ADR-0006 must be read as a pair. ADR-0004 still owns the hand-authored-config-yml + no-sync-extension pillars; ADR-0006 owns the now-superseded hooks pillar. Reading ADR-0004 in isolation today gives the wrong impression of the safety stack.
  • test_omp_hook_shape only checks the shape — not the behavior. A hook with a valid default-export signature that does nothing will pass the pipeline. Behavior validation is a manual / future concern.
  • The deleted TTSR rules' bodies were a model-facing UX surface, not just enforcement. Hook reason strings are shorter. If the model starts asking "what should I do instead?" more often after this change, lengthen the reasons before adding back rule bodies.
  • OpenCode is still untouched. Hooks don't reach OpenCode (no hook surface). Rules never reached OpenCode (no rule loader). Sync-permissions.py stays Claude ↔ OpenCode only. Adding a 4th harness later should follow the same per-harness-safety-stack pattern, not assume hooks/rules port automatically.

Gotchas

  • Regex lastIndex in redact-keys. Each SECRET_PATTERNS entry uses /g flag, which carries lastIndex across calls. redactText() resets it explicitly before each replace(). Don't refactor away the reset; tests across multiple tool_results would otherwise non-deterministically miss matches.
  • guard-curl-pipe's segment splitter treats || as logical-OR (skipped), but the pipe-vs-OR check is positional — cmd[i + 1] !== "|". If you ever extend it to other multi-char operators, mind the order.
  • guard-credentials tokenizer doesn't handle backslash escapes inside double-quoted strings. A path like "~/.aws/credentials\\" would tokenize oddly. Not a security hole (the regex still matches the credential substring), but worth knowing if you debug a weird tokenization case.
  • The install loop guards ([ -f "$hook" ] || continue) protect against a glob that matches nothing. If omp/hooks/pre/ contains no .ts files, the glob expands to itself literally — the guard skips it. Don't remove the guard "because it's redundant".
