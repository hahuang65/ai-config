Guardrail Consolidation

A second tier of guardrails — cloud-destroy, deploy, db-mutation, dd-to-disk, shell-write, broad-chmod, destructive git, and the hardcoded-secret check — was still oh-my-pi TTSR rules: enforced on omp, guidance-only on Claude, and nothing on a future harness.

This migrates all of it into the shared guard core (+ one new capability: write-content inspection). Every command/content guardrail now enforces uniformly across harnesses, conformance-checked. TTSR is retired; rules/ is advisory-only. The change deletes 7 rule files and finishes ADR-0011's consolidation — which is what lets pi drop in next inheriting everything through one adapter.

04 Decision log

Migrate command + content enforcement into the core; retire TTSR high — ADR-0012

Rationale: TTSR is omp-only, so those guardrails weren't enforced on Claude or a future harness. One core = uniform, conformance-checked, and pi inherits it through one adapter.

security.md split — only the hardcoded-secret pattern is hard-blockable high — discussed

Rationale: format-matched key literals are high-confidence; SQL-concat/eval/exec/input-taint are too false-positive-prone to hard-block, so they stay advisory.

Floor = everything except no-shell-write high — you chose (promote both)

Rationale: irreversible/catastrophic/secret/privilege = floor; shell-redirect (a visibility guard) is the lone non-floor and the conformance discriminator no-force-push used to be.

05 Re-entry context

Invariants Content blocking is format-based on purpose (SECRET_LITERAL_PATTERNS) — a placeholder must not fire. The 5 migrated detectors are regex over the whole command; the token detectors (secret/rm/sudo/git) use anyPipeline. No rule may carry condition:/scope: — the gate enforces it.
Coupling Adapters forward write content as content ?? new_string; the conformance probe builder must include content or content policies show a false gap. Floor membership lives in the registry's floor flag, not in the test.
Don't forget pi is the next feature — it inherits all 12 policies via one tier-A extension. The four fuzzy security anti-patterns remain advisory; promoting any to the core needs content-taint analysis, not a regex.
