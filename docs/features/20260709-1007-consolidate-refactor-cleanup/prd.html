Consolidate Refactor & Cleanup — PRD

docs/features/20260709-1007-consolidate-refactor-cleanup  ·  ADR-0015  ·  glossary: Hygiene sweep, Directed refactor

Three catalog components claim behavior-preserving code improvement, and two of them — the review chain's back-to-back code-cleaner and refactor-cleaner steps — overlap by roughly 80%. The fix: one execution engine with two modes. The refactorer agent absorbs all cleanup duties as a new hygiene mode alongside its existing plan mode; both cleaners are deleted; the refactor skill stays as the user-facing front-end and learns to route vague goals to a hygiene sweep instead of rejecting them.

User Stories
Catalog maintainer — exactly one component responsible for post-implementation cleanup, so I never have to explain why two near-identical cleaners run back-to-back.
/build user — the review chain sweeps my changed files once instead of twice, so the post-implementation phase is faster and its report isn't split across overlapping steps.
/refactor user (specific goal) — the plan → approve → execute path unchanged, so directed refactors keep their safety gate.
/refactor user (vague goal) — "clean up the auth module" runs a hygiene sweep instead of being rejected, so a standalone cleanup entry point survives the deletions.
/implement user — the sweep applies SAFE changes automatically and only reports CAREFUL/RISKY findings, so the chain runs unattended without risky deletions slipping through.
/implement-coach user — CAREFUL/RISKY findings surfaced to me for decision while mechanical fixes are applied directly, so the coach-mode ownership split survives the merge.
Catalog maintainer — the engine never commits in either mode, so the contradictory commit instruction cannot resurface.
Catalog maintainer — retired names purged from every skill, agent, reference, and doc, so nothing instructs the model to invoke a component that no longer exists.
Catalog maintainer — the content-check pipeline enforces the new shape and rejects the retired names, so a future edit can't silently reintroduce the split.
Future contributor — "hygiene sweep" and "directed refactor" pinned in the glossary with avoid-lists, so the vocabulary that caused this confusion stays pinned.
/improve-codebase user — its boundary note points at the hygiene sweep instead of two retired components, so its scope contrast stays accurate.
pi / oh-my-pi user — the consolidated components keep working across all harnesses, so the merge doesn't regress the multi-harness contract.
Implementation Decisions
Implemented & fact-checked (2026-07-09). All four slices landed on refactor/consolidate-refactor-cleanup; 13/14 claims confirmed against the tree, 1 corrected (the refactor skill keeps its own never-commit guardrails as defense in depth — only the review chain dropped commit wording). See the Verification Summary in prd.md.
One engine, two modes (ADR-0015). Mode switch driven by input: a numbered plan → plan mode; a changed-file list and no plan → hygiene mode. No new agent is created.
Hygiene duties = union of the two retired cleaners. Dead code, unused imports & dependencies, duplicate consolidation into existing helpers, simplification, language idioms.
Risk vocabulary retained, mode-dependent. SAFE/CAREFUL/RISKY means deletion risk in hygiene mode, transformation risk in plan mode. Recorded in ADR-0015 so nobody "unifies" it later.
Chain shrinks by one step. "Clean up" + "Refactor cleanup" → one "Refactor" step; the coach-mode split (mechanical applied, judgment surfaced) moves into that step's wording.
Goal-specificity routing. The skill's former "reject vague goals" rule is retired; vague goals dispatch hygiene mode on the named area, skipping the plan interview.
Never commit, either mode. Stated in the engine's safety rules; the review chain no longer carries any commit warning. The refactor skill keeps its own never-commit guardrails as defense in depth.
Naming constraints honored. Chain step "Refactor" is prose; the engine keeps refactorer; the skill keeps /refactor — no collision, nothing shadows the built-in /simplify.
Full reference purge. Pipeline skills, orchestrator, improve-codebase, READMEs, authoring contract, and visual guides rewritten to the new shape.
Glossary + ADR already landed this session. Hygiene sweep and Directed refactor entries; ADR-0015 records the shape and the partial reversal of the 20260310 decision.

Further Notes
Supersedes the 20260310 rationale. That research kept refactor standalone because refactor-cleaner owned cleanup. Separation of concerns survives — as two modes of one engine rather than two components.
Context trade. Hygiene mode gives up the inline-session context code-cleaner had, in exchange for keeping cleanup token-churn out of the main session. The changed-file list passed at dispatch is the compensation. As an agent, the engine shares verbatim across all harnesses — no harness-module work expected.
