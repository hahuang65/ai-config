Consolidate Refactor & Cleanup — Diff Review

working tree vs main · branch refactor/consolidate-refactor-cleanup · 2026-07-09 · ADR-0015

The catalog had three components claiming behavior-preserving code improvement, and the review chain ran two of them back-to-back doing ~80% the same job. This diff collapses them onto one engine with two modes: the refactorer agent keeps its plan-execution behavior and gains a hygiene mode that absorbs everything the two retired cleaners did.

The insight that unlocked it: the axis separating the components was never "does it restructure code" — it's automatic hygiene (plan-less, SAFE-only, runs unattended) versus directed transformation (user goal, plan-approval gate). Those are two entry modes of one engine, not three components. A side-effect win: the retired refactor-cleaner carried a "commit with descriptive messages" instruction that contradicted the repo-wide never-commit convention — it died in the merge, and a new never-commit rule in the engine plus rejection assertions in the test pipeline make both regressions unrepresentable.

Decision Log
High — ADR-0015

One engine with two modes, not a merged cleaner or a three-way merge

Rationale: the user wanted the chain step named "refactor", which collides with the /refactor skill unless the merged component is an agent — and the safety cores of the two agents were already identical. Alternatives considered: merge only the two cleaners into an inline skill (rejected: naming collision, and the engine shape unifies the safety core); keep all three and sharpen chain-step boundaries (rejected: the naming confusion and double sweep survive).

High — grill session

Vague goals route to hygiene mode instead of being rejected

Rationale: deleting code-cleaner would otherwise leave no standalone cleanup entry point. The SAFE-only contract replaces the plan gate — that's what makes a gate-less route safe. User picked this explicitly over keeping the rejection.

High — review fix

CONTEXT.md exempt from the rejection scan; harnesses/ included

Rationale: the glossary's _Avoid_ lists must name the retired vocabulary to steer writers away from it — scanning CONTEXT.md would fail on legitimate content. harnesses/ had no principled reason to be exempt, so the reviewer's gap finding was applied there. The exemptions are now spelled out in the check's comment block.

High — documented deviation

Guides updated in Slice 2, not Slice 3 as planned

Rationale: the guide/skill sync check requires any backticked agent in a SKILL.md to appear in its guide.html — deferring guide edits would have broken the gate at the slice boundary. Recorded in tasks.md.

Re-entry Context
Note from present-you to future-you
  • Key invariant: the content checks are the contract. Never edit test_retired_cleaners / test_agent_refactorer assertions to make a doc edit pass — change the doc.
  • Key invariant: hygiene mode applies SAFE only. If a future edit lets it auto-apply CAREFUL/RISKY, the gate-less chain step and the gate-less vague-goal route both become unsafe — the no-gate design depends on it.
  • Non-obvious coupling: gather_skill_content follows a SKILL.md's own reference links — a phrase moved from review-chain.md into a file the skill doesn't link stops counting. And any backticked agent name in a SKILL.md must appear as text in that skill's guide.html.
  • Gotcha: the meta-suite (make test/meta) plants fixture files inside the repo while running — don't run the content gate (or a hygiene sweep) concurrently, or you'll chase phantom failures.
  • Don't forget: run make install after committing — ~/.claude/skills/code-cleaner and ~/.claude/agents/refactor-cleaner.md are dangling symlinks until the prune runs.
  • Don't forget: commit CONTEXT.md, docs/adr/0015, and the feature directory with the code changes; leave harnesses/claude/settings.json unstaged (pre-existing, unrelated).
  • Pre-existing failures (not this diff): install-behavior expects harnesses/pi/extensions/subagent/{index,agents}.ts which don't exist in the repo; the meta valid-repo check cascades from it.
