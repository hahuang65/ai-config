01

omp baseline install

AFK Blocked by: none — start immediately
User stories 010203 050607 081415 232425 30

The minimum that makes omp a first-class peer of Claude / OpenCode. After this slice, an omp user runs ./install.sh and immediately gets all this repo's skills, commands, agents discoverable in omp at native priority, with sane approval defaults. Rules are symlinked but inert until slices 2 / 3.

Acceptance criteria
  • New file omp/config.yml with tools.approvalMode: write + per-tool prompts for bash, browser, ssh, eval. No MCP, theme, or provider entries.
  • install.sh gains an omp section adjacent to the OpenCode block that symlinks skills/, commands/, agents/, rules/, and omp/config.yml into ~/.omp/agent/.
  • Skill / command duality skip-rule is NOT applied for omp — all commands install.
  • rules/development-workflow.md deleted from the repo.
  • Running ./install.sh against a clean $HOME produces resolvable symlinks at all expected paths.
  • Running omp after install lists this repo's skills under the native source (priority 100), not the Claude fallback.
  • Claude Code regression check: rules still render in system prompt, permissions unchanged.
  • OpenCode regression check: opencode/ unchanged byte-for-byte.

03

TTSR — 8 enforcement rules with regex conditions

AFK Blocked by: Slice 1
User stories 040910 111213 161729

omp's per-pattern enforcement comes online. Eight TTSR rules cover what Claude's denylist + curl hook achieve on the Claude side. Each rule body follows omp's authoring guidance: what the model just tried, why blocked, the right alternative, instruction to re-plan.

Acceptance criteria
  • security.md gains TTSR frontmatter: condition array for secrets / SQL concat / user-input → file APIs / eval / shell injection + scope tool:edit, tool:write, tool:bash.
  • git-workflow.md gains TTSR frontmatter: condition array for force-push, --no-verify, --no-gpg-sign, git clean -f, broad git reset --hard.
  • Six new TTSR files created: no-curl-pipe-interpreter, no-rm-rf-root, no-cloud-destroy, no-shell-write, no-credentials-read, no-deploy.
  • In omp, typing git push --force origin main in a bash call aborts with the git-workflow body injected.
  • Typing curl … | bash aborts with no-curl-pipe-interpreter body injected.
  • Reading a path matching .aws/credentials aborts with no-credentials-read body injected.
  • Spot-check at least 4 of 8 TTSR rules fire on a trigger pattern.
  • Claude regression: all 8 rule bodies still appear in Claude's system prompt; frontmatter inert.
05

omp surface validation in test pipeline

AFK Blocked by: Slices 1, 2, 3
User stories 2022

Four new consistency checks future-proof the omp surface against drift. Follows the existing per-file iteration + pass/fail counter pattern. Meta-test gets four matching negative cases that prove each check catches its target failure.

Acceptance criteria
  • test_ttsr_rule_frontmatter: for each rule with condition:, asserts description: present, condition: is non-empty list of strings, scope: if present is string or comma-list.
  • test_rulebook_rule_frontmatter: for each rule without condition:, asserts description: present, condition:/alwaysApply: absent.
  • test_omp_install_targets_exist: parses omp install block in install.sh; every symlink source must resolve to an existing file.
  • test_omp_config_yaml_valid: omp/config.yml parses as valid YAML.
  • Four matching negative cases added to test-pipeline-self-test.sh, one per new check, with plant → run → assert-fail → restore pattern.
  • scripts/test-pipeline.sh passes cleanly against the repo after slices 1–3 are in.
  • scripts/test-pipeline-self-test.sh exits zero — all four new negative cases fire.
