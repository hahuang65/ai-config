01
RCI-01 · Input to scope

Accept resilient pull-request targets

Turn copied GitHub pull-request links and concise identifiers into the same normalized pull-request scope.

Can run unattended · AFK
StatusComplete
Blocked byNone
Stories1, 2, 3, 25, 28
Test surfacePure GitHub target parser

What to build

Add one side-effect-free parser for GitHub pull-request URLs and gh: identifiers, then carry its normalized output through existing pull-request resolution and CLI help.

Acceptance criteria

  • A canonical GitHub pull-request URL resolves through the parser and existing review path.Complete
  • Trailing paths such as /changes, plus query strings and fragments, normalize to the numeric pull request.Complete
  • The exact gh:owner/repository/pull/number identifier produces the same normalized target and rejects URL suffixes, queries, and fragments.Complete
  • Malformed structure, unsupported hosts, embedded credentials, control characters, and oversized values fail before provider or Git activity.Complete
  • CLI help names the accepted pull-request URL and identifier forms without changing existing options.Complete
02
RCI-02 · Local repository

Resolve local-first pull-request shorthand

Protect exact local branch names while making pull/59 and bare numbers useful against an unambiguous GitHub remote.

Can run unattended · AFK
StatusComplete
Blocked byRCI-01
Stories8–13, 25, 28
Test surfaceresolveReviewTarget

What to build

Apply exact local branch matching before shorthand, identify the GitHub repository from remotes, and convert unambiguous shorthand into a normalized pull-request target.

Acceptance criteria

  • An exact local branch named pull/59 wins over pull-request shorthand.Complete
  • An exact numeric local branch wins over bare-number pull-request shorthand.Complete
  • Without an exact branch, pull/59 and 59 select the same pull request.Complete
  • A GitHub origin is selected before other remotes.Complete
  • When origin is not GitHub, exactly one other GitHub remote is accepted.Complete
  • No GitHub remote or multiple remaining GitHub remotes produces a corrective ambiguity error and no provider review.Complete
03
RCI-03 · Fresh local branch

Freeze the current branch descendant

Fetch inside review isolation and choose a branch tip by ancestry without touching source repository metadata.

Can run unattended · AFK
StatusComplete
Blocked byRCI-02
Stories14–18, 20, 27
Test surfaceWorkspace plus target resolver

What to build

Move branch freshness work into the disposable local snapshot, fetch the matching remote there, compare local and fetched tips by ancestry, and freeze the selected range.

Acceptance criteria

  • Fetch changes only the disposable review workspace and leaves source local refs, remote-tracking refs, and fetch metadata unchanged.Complete
  • Mutable branches resolve their base from the fetched repository default branch, while explicit immutable ranges remain unchanged.Complete
  • The descendant tip wins whether it is local or fetched remote state.Complete
  • branch and origin/branch apply the same descendant selection.Complete
  • Diverged tips stop with an explicit message, and only Git's ordinary negative ancestry status means false; operational ancestry failures retain corrective diagnostics.Complete
  • Fetch failure stops before validation rather than using stale remote-tracking state.Complete
04
RCI-04 · Direct pull request

Acquire a pull request from any directory

Use the repository named by an explicit GitHub target to create a safe review workspace without requiring a local checkout.

Can run unattended · AFK
StatusComplete
Blocked byRCI-03
Stories6, 7, 21–24, 27
Test surfacecreateReviewWorkspace and CLI

What to build

Add direct authenticated GitHub acquisition to the workspace lifecycle, preserve the untrusted no-materialization boundary, evaluate A5 through canonical SSH repository identity, and run the existing pull-request review from the acquired source.

Acceptance criteria

  • An explicit GitHub pull-request target starts successfully outside every Git repository.Complete
  • The same target started inside a different repository uses only the repository named by the target.Complete
  • Private repository acquisition uses authenticated GitHub access without retaining or logging credentials.Complete
  • The standalone parent classifies trust before materialization; an Untrusted pull-request head remains unmaterialized, while a Trusted head materializes exactly its selected OID.Complete
  • The actual pull-request head repository, including a fork, supplies the identity used for A5 classification.Complete
  • Canonical SSH identity can activate global or system A5 configuration, while repository-local configuration cannot grant trust.Complete
  • Push is disabled and success, failure, and interruption clean only the recorded materialized and acquisition paths.Complete
05
RCI-05 · Direct branch

Acquire and freeze a GitHub branch

Extend direct acquisition to branch URLs and identifiers, including slash names and default-branch comparison.

Can run unattended · AFK
StatusComplete
Blocked byRCI-04
Stories4–7, 19–24, 27
Test surfaceParser, resolver, workspace, and CLI

What to build

Normalize GitHub branch URLs and gh: identifiers, resolve the longest existing slash-bearing branch prefix, acquire its repository, and freeze the change against the remote default branch under the same trust boundary as pull requests.

Acceptance criteria

  • A GitHub tree URL and equivalent gh: identifier resolve the same branch.Complete
  • Slash-bearing branch names resolve through the longest existing branch-name prefix when a URL could include a repository path.Complete
  • The repository's current remote default branch supplies the comparison base.Complete
  • The base and branch head are frozen to immutable commits before validation starts.Complete
  • Direct-branch A5 classification requires strict pre-acquisition provider ID and canonical identity, post-acquisition metadata queried by that ID, and exact selected/default OID equality with the clone; unrelated refs cannot affect scope or trust, and Trusted materialization receives only the selected OID.Complete
  • Missing repositories, default branches, or requested branches fail with corrective errors and recorded cleanup.Complete
