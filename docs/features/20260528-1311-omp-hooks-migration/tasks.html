01

omp/hooks install + guard-rm + delete no-rm-rf-root

AFK Foundation Complete Blocked by: none
User stories 010411 1521

The foundational tracer bullet: install pipeline knows how to symlink hooks; first hook is wired; first TTSR rule is deleted. Establishes the authoring pattern slices 3–6 follow. After this slice, rm -rf ~ blocks via the hook with broader coverage (catches find / -delete, process substitution wrappers) than the deleted regex could.

Acceptance criteria
  • New repo dir omp/hooks/pre/ exists with guard-rm.ts; omp/hooks/post/ springs into being in slice 6. omp/hooks/README.md documents the structure.
  • New file omp/hooks/pre/guard-rm.ts exports default function (pi: HookAPI), registers a tool_call handler that filters bash, parses argv structurally (process-substitution-aware via extractSubstitutions), and returns { block, reason } for broad rm/find against /, ~, $HOME, ${HOME}, * and trailing-slash variants. . and .. are deliberately NOT in BROAD_TARGETS (find . -name "*.pyc" -delete is common cleanup).
  • install.sh gains a new section adjacent to omp/extensions/: mkdir extended for hooks/{pre,post}/, two symlink loops covering *.ts and *.js with [ -f ] guards. README.md skipped via glob filter.
  • rules/no-rm-rf-root.md deleted via git rm; dangling symlinks unlinked.
  • Running ./install.sh produces a resolvable symlink at ~/.omp/agent/hooks/pre/guard-rm.ts.
  • In an omp session, rm -rf ~ aborts with the hook's reason; find / -delete also aborts.
  • Claude regression: claude/settings.json's Bash(rm -rf *) deny still applies.
  • OpenCode regression: deletion is invisible (OpenCode never loaded rules).
  • omp/config.yml unchanged byte-for-byte.
Implementation note guard-rm.ts is ~120 lines with structured argv parsing, process- and command-substitution extraction, and broad-target detection for both rm and find. Targets recognized as broad: /, ~, *, $HOME, ${HOME}, and trailing-slash variants (~/, $HOME/, ${HOME}/). . and .. were removed during post-review hardening after find . -name "*.pyc" -delete was identified as a common false-positive. The recursion into substitutions handles bash <(rm -rf /), $(rm -rf ~), and backtick variants.

guard-credentials + delete no-credentials-read

AFK Pre-hook Complete Blocked by: Slice 1
User stories 010519 21

Third pre-hook migration. Single hook covers read, edit, and bash with per-tool structured input checks: file tools check event.input.path; bash parses argv for credential-reading subcommands. Same 8 path patterns the deleted TTSR covered. Bypass-fix: structured event.input.path checking eliminates over-firing on prose mentions — only actual tool inputs trigger.

Acceptance criteria
  • New omp/hooks/pre/guard-credentials.ts (~135 lines): 8 credential-path regexes with case-insensitive SSH keys, 19 credential-reader commands (cat/awk/grep/sed/head/tail/less/more/tac/nl/od/strings/xxd/hexdump/vim/vi/nano/emacs/cp/mv/rsync/scp), per-tool dispatch.
  • Fires on read/edit when input.path matches a credential pattern; fires on bash when any segment (split on |/;/&&/||) is a credential-reader command with a credential-path arg. Recurses into process/command substitutions.
  • All 8 patterns covered: .aws/credentials, .kube/config, .ssh/id_* (case-insensitive), .netrc, .pgpass, .npmrc, .secrets.*, anything literally named credentials.
  • rules/no-credentials-read.md deleted via git rm; dangling symlinks unlinked.
  • Pipeline passes cleanly (401/0 — net −1).
  • In omp: awk '{}' ~/.aws/credentials aborts (bash branch); cat ~/.ssh/id_RSA aborts; prose mentions of .aws/credentials do NOT fire.
  • Claude regression: claude/settings.json's Read(**/.aws/credentials) deny still applies.
  • OpenCode regression: invisible.
05

guard-sudo + delete no-sudo

AFK Pre-hook Complete Blocked by: Slice 1
User stories 010308 21

Fourth pre-hook migration. guard-sudo.ts blocks any sudo invocation including wrapper bypasses: bash <(sudo …), find … -exec sudo …, python -c "os.system('sudo …')".

Acceptance criteria
  • New omp/hooks/pre/guard-sudo.ts (~30 lines) — simple \bsudo\s regex on event.input.command (matches the literal substring inside any wrapper shape).
  • Catches: sudo apt, bash <(sudo apt), find … -exec sudo …, python -c "os.system('sudo apt')". Avoids false positives: pseudo-random, sudoers, cat sudo.txt, /usr/local/bin/sudo.
  • rules/no-sudo.md deleted via git rm; dangling symlinks unlinked.
  • Pipeline passes cleanly (400/0 — net −1).
  • In omp, all four wrapper shapes abort.
  • Claude regression: invisible (Claude already prompts on sudo via approval flow).
  • OpenCode regression: invisible.
Implementation note Original PRD framing claimed sudo was "bypass-prone" via bash <(sudo) / find-exec / python -c. After deeper analysis, the deleted TTSR rule's scope: tool:bash configuration already prevented prose over-firing, and the \bsudo\b regex would catch the wrapper shapes. This migration is primarily for consistency with the other migrated guards. The hook does have a marginal precision win — \bsudo\s vs. \bsudo\b avoids false positives like cat sudo.txt.
06

redact-keys post-hook (net-new)

AFK Post-hook Complete Blocked by: Slice 1
User stories 020607 1821

The single post-hook this PRD adds. Net-new capability — TTSR can't mutate tool_result content. redact-keys.ts registers a tool_result handler that filters to read, edit, and bash (skipping event.isError === true), and runs multi-pattern redaction: API_KEY=, SECRET=, TOKEN=, PASSWORD=, BEARER=, AUTH(_TOKEN)?=, ACCESS_KEY=, PRIVATE_KEY=, HTTP Bearer <token>, AKIA[A-Z0-9]{16}, GitHub tokens (classic gh[pousr]_ + fine-grained github_pat_), JWT three-segment. Placeholder allowlist skips xxx, your-, your_, placeholder, example, redacted, <…>, …, all-same-char strings.

Acceptance criteria
  • New omp/hooks/post/redact-keys.ts registers tool_result, returns { content } with redacted text blocks. ~100 lines: REDACT_TOOLS set, isPlaceholder predicate, 5 secret-pattern entries (11+ shapes fold into 5 regex groups).
  • Tool filter is Set(["read", "edit", "bash"]). Dropped fetch from the original PRD list (omp's web fetching goes through read); edit was added during post-review hardening — it can echo file contents back to the model the same way read does.
  • 11+ secret pattern variants covered: API_KEY/SECRET/TOKEN/PASSWORD/BEARER/AUTH/ACCESS_KEY/PRIVATE_KEY (8 inside one KEY=value alternation regex), HTTP Bearer header, AWS AKIA*, GitHub tokens (classic gh[pousr]_ + fine-grained github_pat_), JWT three-segment shape.
  • Placeholder skip works on xxx, your-/your_, placeholder, example, redacted, <…>, …, and all-same-char-of-length-≥8 strings. API_KEY=YOUR_KEY_HERE matched by regex but skipped; API_KEY=abc123def4567890 redacted.
  • event.isError === true results pass through untouched (early return).
  • Pipeline passes cleanly (403/0 — +3 for the new hook's three shape assertions).
  • In omp: a bash printenv returning API_KEY=abcdef1234567890 is redacted to API_KEY=[REDACTED]; a read of a fixture file with API_KEY=YOUR_KEY_HERE passes through unchanged.
  • Claude/OpenCode regression: net-new omp-only — neither affected.
Implementation note The 11-pattern count folds into 5 regex entries because the 8 KEY=value variants (API_KEY, SECRET, TOKEN, PASSWORD, BEARER, AUTH(_TOKEN)?, ACCESS_KEY, PRIVATE_KEY — last added during authoring as same-shape) share a single key-name alternation regex. The 4 distinct-shape patterns (http-bearer, aws-key-id, github-token, jwt) each get their own entry. Post-review hardening: edit added to REDACT_TOOLS (it echoes file contents); the github_pat_ fine-grained PAT format was folded into the github-token regex's alternation. Net: 5 entries, 11+ secret shapes covered.
