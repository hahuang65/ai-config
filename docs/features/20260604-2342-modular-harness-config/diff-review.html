Modular Harness Config & Shared Guardrails

SummaryKPIsArchitecture Before/AfterGuardrail flowFile map TestsReviewDecisionsRe-entry

The repo's security guardrails were written four-plus times — once per oh-my-pi hook (guard-rm/sudo/curl-pipe/credentials.ts) and again as a Claude shell hook — exactly the drift ADR-0004 predicted. Adding a third harness (pi) would have meant a fifth copy.

This change collapses all of it into one shared guard core that every harness routes through, and makes each harness a pluggable module so the installer is a generic loop. Security is now defined once and projected per harness (ports-and-adapters), with two CI invariants — a conformance test (every harness enforces the mandatory floor) and an isolation test (no harness pollutes another).

The headline: the change removes more than it adds while gaining a registry, a conformance matrix, an isolation guarantee, and a clean slot for pi — and a security review caught a real bypass regression that's now fixed and tested.

03 Before / after

Repo layout

Before

  • Per-harness config at top level: claude/, omp/
  • Mixed with shared dirs; no clean unit to add/remove
  • install.sh — two hand-written ~40-line blocks

After

  • harnesses/{claude,omp,pi}/ self-contained modules
  • Each ships a sourced manifest.sh (config root, consumed categories, install hook)
  • install.sh — generic loop; add/remove = a directory

Guardrail enforcement

Before — duplicated

  • 4 oh-my-pi hooks each with its own matcher logic
  • + a separate Claude deny-curl-to-interpreter.sh
  • Logic forked across TS + shell; drift inevitable (ADR-0004)
  • No guarantee a harness covers a given guardrail

After — projected

  • One shared/guard-core.ts evaluate()
  • Registry of policy IDs + floor flags
  • Thin adapters: omp tier-A in-process, Claude tier-B shim; static denylist kept as defense-in-depth
  • Conformance test proves floor coverage; isolation test proves no pollution

Cross-harness pollution

Before

  • oh-my-pi scavenged ~/.claude/skills at priority 80
  • Changes leaked across harnesses, invisibly

After

  • Cross-discovery disabled (enableClaudeUser: false …)
  • Push-only sharing; isolation test fails CI on any leak

07 Code review

A code-reviewer pass ran against the guardrail code. Findings below; all blocking items fixed TDD-style before this review.

Good

Detection written once

The 5→1 consolidation removes the documented drift surface; the shared shell-parsing helpers (tokenize, separators, substitution recursion) are reused by every detector.

Two invariants as a contract

Conformance (coverage) + isolation (no pollution) are CI-checked, each with a test-the-test fixture so they can't silently pass.

Net-negative diff

Removes more than it adds while adding real capability — and ships a clean, pending pi slot.

Bad — found & fixed

CRITICAL · no-space rm chain bypass ✓ fixed

echo;rm -rf ~ slipped through — isBroadRm tokenized without splitting on separators. Now splits per segment. +test

HIGH · lowercase env-var regression ✓ fixed

http_proxy=x cat ~/.aws/credentials bypassed the credential reader (uppercase-only regex introduced during consolidation). Restored case-insensitive skip. +test

HIGH · merged flag & absolute git ✓ fixed

git push -fv and /usr/bin/git push --force evaded force-push detection. Now matches merged short clusters and */git. +tests

HIGH · find valued-flag-before-path ✓ fixed

find -maxdepth 1 ~ -delete mis-read the path. Now skips valued flags' arguments. +test

Ugly — accepted tech debt

Two similar splitters

splitOnPipe (pipe-only) and splitOnSeparators (all operators) overlap. Semantically distinct, but a candidate for /improve-codebase.

Detectors don't gate on tool name

By design (adapters normalize), but a buggy future adapter sending command on a non-bash tool could surprise. Mitigated by the typed normalized shape.

Questions — resolved

Instruction file (story 21)

Resolved: AGENTS.md is an authoring contract, not a neutral global instruction — left unwired; mechanism present in the manifest. Acknowledged by you.

Conformance harness-list drift

Live test now derives the harness list from the adapters under test, so it can't diverge when pi is promoted.

08 Decision log

ADR-0010 · topology

Single modular repo, pluggable harness modules high — discussed

Rationale: add/remove-a-harness is the primary driver; one repo + curated push beats separate repos (drift) or submodules (friction).

Rejected: separate repos per harness; git submodule for shared content.

ADR-0011 · guardrails

Ports-and-adapters projection, not config sync high — discussed

Rationale: two harnesses share a near-identical TS hook API, so the detection logic can be literally shared; Claude reaches it via a thin shim. Supersedes ADR-0004's decoupling (whose only alternative was the brittle sync-permissions.py compiler).

HITL

harnesses/ layout + sourced manifest.sh high — you chose

Rationale: structural separation of modules vs shared dirs; a sourced manifest lets each module own its install quirks without a parser. Accepted the import-path/churn cost (caught by tests).

contract

Floor as a per-policy boolean flag high — discussed

Rationale: co-locates "is baseline?" with the policy; conformance filters on it; tightening to total coverage is a one-line change. Not positional, not hard-coded.

implementation

Registry is shared/policy-registry.ts, not a policies/ dir medium — inferred

Rationale (inferred): a single small file is simpler than a directory for 5 policies; ADR-0011's prose says policies/. Revisit if the registry grows or per-policy intent docs are wanted.

09 Re-entry context

Key invariants The guard core must stay dependency-free (runs under bun without node_modules). Adapters resolve it by relative import via symlink realpath — don't switch to --preserve-symlinks. Cross-discovery flags in config.yml must stay false. Every floor policy needs a conformance probe (the test enforces this).
Non-obvious coupling Adapters ↔ core agree on the normalized {tool,command,path} shape — change one, change both adapters + the live conformance probes. The Claude shim is referenced by absolute path in settings.json (~/.dotfiles/ai/harnesses/claude/hooks/guard.ts) — moving the repo or the file breaks it.
Gotchas The pre-commit pipeline now installs into a temp HOME and runs bun test — slightly slower, and bun must be on PATH. HARNESSES_DIR overrides the modules root (used by the behavior test). Adding a .test.ts under harnesses/omp/hooks/pre/ would get symlinked as a hook — keep adapter tests in test/.
Don't forget pi enforcement is a deferred follow-up (slot only). Story 21's per-root instruction file is unwired by choice. ADR-0011 prose says policies/ but the impl is shared/policy-registry.ts — reconcile if it bothers you. No CHANGELOG in this repo.
