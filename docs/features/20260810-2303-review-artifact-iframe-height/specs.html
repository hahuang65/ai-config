Review artifact workflow · Compatibility repair

Spec

Keep the reviewed artifact full-height in Firefox, regardless of viewport shape or change-bar state.

One browser-derived layout contract

The artifact iframe occupies every pixel left for it by the review shell grid.

Focused repair
Problem statement

A full-height panel can contain a collapsed artifact.

In Firefox, the artifact iframe can remain near its intrinsic height of about 150 pixels while the artifact panel and conversation panel fill the available viewport.

The reviewed document itself lays out correctly when opened directly, so the failure belongs to the review shell.

This defect makes most of a tall review surface unusable and can hide content far above an apparently empty panel.

Solution

Let the grid own the iframe height.

Previous behavior

When the change bar is hidden, it produces no grid item. Without explicit placement, grid auto-placement puts the iframe in the first intrinsic auto row instead of the remaining second row.

The old height: 100% then fills that intrinsic row, leaving the iframe near its 150-pixel intrinsic height.

Implemented behavior

The iframe is explicitly placed in grid row 2 and stretches across the row that remains after the optional change bar.

The shell removes the percentage height and uses CSS layout only, with no measured height or JavaScript sizing state.

User stories

Observable outcomes

  1. As a reviewer on a wide viewport, I want the artifact to fill its panel, so that I can use the complete review surface.
  2. As a reviewer on a tall viewport, I want the artifact to grow with the panel, so that Firefox does not leave a large empty region below it.
  3. As a reviewer on a narrow viewport, I want the stacked artifact region to retain its intended height, so that the artifact and conversation remain usable without horizontal overflow.
  4. As a reviewer examining the latest artifact revision, I want the artifact to fill the space below the visible change bar, so that revision navigation does not collapse the document.
  5. As a reviewer without a visible change bar, I want the artifact to begin at the panel’s content edge, so that no unexplained gap appears above it.
  6. As a keyboard user, I want the existing shell order, controls, focus indicators, and iframe title to remain unchanged, so that the layout repair does not alter navigation or meaning.
  7. As a workflow owner, I want the iframe size to remain derived by CSS Grid, so that viewport changes do not introduce script state, resize listeners, or timing failures.
  8. As a maintainer, I want real Firefox evidence across representative viewport shapes, so that an intrinsic-height regression cannot pass unnoticed.
  9. As a security-conscious reviewer, I want the existing iframe sandbox and message boundaries to remain unchanged, so that a layout repair does not broaden reviewed-document privileges.
Implementation decisions

A single production boundary

Review shell layout

The review shell layout is the only production module that changes.

The change bar occupies the intrinsic first row when visible. The artifact iframe is explicitly placed in row 2 and stretches through that remaining bounded row without a percentage height.

Geometry contract

The iframe’s inline edges match the artifact panel’s content edges.

Its bottom edge matches the panel’s content bottom.

Its top edge matches either the panel’s content top or the visible change bar’s bottom.

State ownership

Change-bar visibility remains in the existing hidden-state mechanism.

Iframe height remains browser-derived layout, not application state.

Accessibility

The semantic landmarks, iframe title, document order, focus behavior, artifact scrolling, and narrow-page scrolling remain unchanged.

Runtime boundaries

The shell markup, reviewed document, artifact bridge, sandbox policy, and message protocol do not change.

Testing decisions

Firefox geometry is the stable seam.

The review shell layout is tested directly through its rendered browser surface using the existing Firefox WebDriver BiDi pool.

Tall1646 × 2063 CSS pixels · regression case
  • The Firefox RED run failed only with the change bar hidden: the iframe bottom missed the panel content bottom by 676, 325, and 1839 pixels in the wide, narrow, and tall viewports. All three visible-bar measurements already passed.
  • Each viewport measures the iframe and artifact panel with the change bar hidden.
  • Each viewport then exposes the change bar through real review behavior and measures the remaining artifact row again.
  • Geometry assertions allow a one-pixel rendering tolerance and compare edges rather than fixed output heights.
  • A deliberately short reviewed document ensures that intrinsic iframe height remains visible when the shell contract fails.
  • The narrow case also preserves stacked ordering and the existing no-horizontal-overflow evidence.
  • Declaration-text assertions are not authoritative because the required behavior is rendered geometry.
Browser requirement: Firefox remains mandatory and must not be skipped when unavailable.
Out of scope

Boundaries that stay fixed

  • No changes to the conditional UI mockup feature or its worktree.
  • No review-shell markup, interaction, persistence, message, or approval changes.
  • No JavaScript height measurement, resize observer, viewport listener, or inline sizing.
  • No reviewed-document CSS changes and no document-to-shell height protocol.
  • No change to browser support policy or the mandatory Firefox evidence gate.
Further notes

Compatibility, not redesign

This repair preserves the review artifact workflow established by ADR-0018.

The change should be judged by consistent rendered geometry, not by a specific CSS declaration.
