Review Change — Spec

A concrete shipping gate for intent, correctness, evidence, documentation, and lint—separate from optional architectural exploration.

THE CORE DECISION

/review-change becomes mandatory at the end of /build. /review-code stays available, but speculative deepening no longer blocks feature completion.

Fixed validation kernel

Evidence, not confidence.

The order is stable. Each mutation restarts from the earliest stage it could invalidate, and the final report is rendered only from the validated state.

Adversarial review

Fresh full-change pass against Authoritative intent, with specialist database Findings when relevant.

Targeted evidence

The smallest relevant tests, checks, screenshots, or provider CI evidence. No duplicate full suite.

Documentation

Find change-caused gaps and stale claims. Repair only in modes that permit mutation.

Lint

Finish with deterministic checks, then cold-fact-check the canonical HTML artifacts in place.

Ownership modes

One kernel, four authority levels.

AI build

Repair objective issues

  • Up to three fix/recheck rounds per stage
  • Source changes restart at adversarial review
  • Final decision stays human-owned
Coached build

The user keeps the keyboard

  • Code and test Findings are guided, not auto-fixed
  • Docs and formatting may be mechanical
  • Every source or test fix gets a fresh review
Standalone CLI

One isolated read-only gate

  • Snapshots tracked and untracked working state
  • Runs pi inside a disposable ~/.review-orchard/ clone
  • Disables push and never invokes the fixer
  • Retains HTML, terminal output, and PR Markdown for pull-request targets
Pull request

Local and read-only

  • Detached under ~/.review-orchard/<project>-<intent>
  • Untrusted heads stay no-checkout and object-only
  • No branch edits or provider mutations
  • Copyable review Markdown for manual posting

A worktree is not a sandbox

Remote pull requests do not run local project commands unless explicitly trusted or covered by a documented sandbox. Untrusted heads are attached with --no-checkout and inspected through immutable Git objects so checkout hooks and content filters cannot run. Static analysis and provider CI remain available. Pull requests whose originating repository has its primary working tree under ~/Projects/a5/ are trusted by convention.

Canonical specification

Durable intent and acceptance contract.

Problem statement

Before this change, the build pipeline ended with architectural exploration even though completion needed an adversarial decision about whether the implemented change satisfied approved intent. Implementation also owned overlapping review, documentation, fact-check, and diff-visual responsibilities, and there was no equivalent safe standalone pull-request workflow.

Solution

Introduce Review change as mandatory Build Phase 5, as a standalone pull-request or local-range skill, and as a harness-independent executable backed by one isolated foreground pi process. It runs a fixed validation kernel, separates severity from action ownership, uses independent reviewer and fixer contexts, and presents mode-appropriate self-contained HTML: build mode uses review-artifact with complete chat fallback, while standalone modes open a results-only report once in the browser and finish without approval.

Implementation decisions

  • Review change replaces review-code as mandatory Phase 5; review-code remains optional standalone architectural exploration.
  • Phase 4 owns TDD, full verification, and refactorer hygiene. Phase 5 owns adversarial review, targeted evidence, documentation, lint, conditional database review, canonical-artifact fact-checking, and the final report.
  • Build intent comes from approved canonical specs.html and tasks.html. Pull-request intent comes from sanitized provider metadata with explicit user context taking precedence.
  • Every adversarial pass dispatches a fresh read-only Change reviewer. The decision ledger is its only cross-round memory.
  • Severity and action are independent; uncertain actions become ask-user.
  • AI build mode permits three automatic repair rounds per stage. Coached mode preserves source/test ownership. Every standalone CLI target, explicit branch or range, and pull request is read-only and never invokes Change fixer.
  • Untrusted heads use detached no-checkout worktrees and immutable Git-object inspection. Only explicit trust, a documented sandbox, or A5 origin authorizes project execution.
  • Build-mode report decisions flow through review-artifact foreground polling; only explicit approval clears the build gate.
  • Standalone reports are results-only HTML opened once in the browser, without review-artifact polling, disposition controls, or approval.
  • The report remains portable semantic HTML, and build mode has a complete chat fallback.
  • Canonical feature HTML is corrected in place and must reach an idempotent clean fact-check pass. No automatic diff-review artifact is generated.
  • The standalone executable reuses the canonical skill through pi --mode json --print --no-session, passes external values without shell interpolation, rejects nested gate execution, propagates the selected model to mandatory Review change subagents, forwards SIGINT/SIGTERM to the foreground child, keeps lifecycle signal listeners active through workspace cleanup and final Summary dismissal, then removes them after terminal restoration, reports target resolution, isolation, adversarial review, targeted evidence, documentation, lint, report generation, cleanup, elapsed time, and final outcome through a color-coded full-screen TTY with NO_COLOR support, navigable per-stage logs, and a plain non-TTY fallback, propagates one lifecycle AbortSignal through setup and child subprocesses, retains signal status through cleanup, validates the single generated HTML report, activates Firefox, and opens its file: URL through a macOS Apple event, or uses the platform HTML viewer elsewhere, after successful validation without waiting for browser closure, records its path, runs exact workspace cleanup before cancellation teardown, then keeps the complete Ctrl-D/Ctrl-U-scrollable parent and assistant summaries in the final TTY stage without replacing the pipeline/log layout until Ctrl-C exits the completed review, with Ctrl-D dedicated to downward scrolling and q, x, and Escape ignored there, then removes the input listener, restores terminal state, pauses stdin so the process exits, and prints the summaries normally only for non-TTY output.
