A browser review loop now lives inside the repo.

Before this feature, the repository had no executable artifact-review surface. The substantive addition is a dependency-free local runtime that turns any existing HTML file into a sandboxed, annotatable review session and carries exact feedback back to the agent through a durable foreground poll.

02 · Architecture

Five layers, one narrow purpose

flowchart TD
        CLI["Command seam\nopen · poll · end · stop"] --> DAEMON["Daemon lifecycle\nhealth · start · shutdown"]
        DAEMON --> SERVER["Loopback HTTP server\nroutes · SSE · file watch"]
        SERVER --> STORE["Durable session store\natomic JSON · event queue"]
        SERVER --> SHELL["Review shell\nconversation · decisions · presence"]
        SHELL --> FRAME["Opaque sandbox iframe"]
        FRAME --> BRIDGE["Artifact bridge\nelement + text anchors · snapshot"]
        BRIDGE --> AUDIT["Layout audit\nescape · clipping · occlusion"]
        STORE -.-> CLI
        SERVER -.->|"reload + replies"| SHELL

Command + daemon

Starts exactly one identified loopback service, rejects an occupied foreign port, opens the platform browser, and keeps the agent waiting in a foreground long poll.

Server + store

Routes browser and agent traffic, canonicalizes artifact identity, serializes state mutations, writes atomically, and delivers queued events exactly once.

Two browser contexts

The trusted parent shell owns network calls and conversation state. The reviewed artifact runs as an opaque-origin sandbox with only an injected bridge.

03 · Capabilities

The substantive behaviors

runtime/assets/bridge.js: 8–239

Element and exact-text annotations

Hover targeting generates bounded CSS selectors and nearby text. Selection targeting additionally records start/end node paths and offsets so feedback can identify a precise range rather than only a containing element.

runtime/session-store.mjs: 9–141

Durable, path-keyed sessions

A SHA-256-derived key identifies the canonical real path. Promise serialization prevents mutation races; temporary-file rename makes each persisted update atomic; event removal happens in the same mutation that returns it.

runtime/server.mjs: 92–252

Indefinite foreground polling

The poll first checks durable state, then waits on an in-process event. Client disconnect returns an interrupted state without deleting queued feedback. There is no runtime poll deadline.

runtime/server.mjs: 194–229

Live reload and presence

A debounced file watcher emits SSE reload events. The shell refreshes only the iframe, attempts scroll restoration, restores annotation mode, and displays whether the agent is listening or working.

runtime/assets/shell.js: 29–105; session-store.mjs: 35–54

Visible, persistent conversation

Queued annotations can be removed before sending. Successfully submitted element annotations and freeform messages render as “You” messages and persist alongside agent replies across full-page reloads.

runtime/assets/layout-audit.js: 1–182

Stable severe-layout evidence

Two geometry samples report only persistent material escape, accidental text clipping, and near-total required-control occlusion. Explicit truncation, scroll containers, masks, and intentional regions are suppressed.

runtime/http.mjs: 1–117; artifact-files.mjs: 1–55

Local attack-surface controls

Loopback binding, Host and Origin checks, 256 KiB body bounds, per-field limits, no-sniff responses, real-path file checks, and sibling-only asset serving constrain untrusted browser input.

runtime/shell.mjs: 1–53

Source-preserving sandbox injection

The server injects bridge scripts only into the served response. The saved artifact is untouched, and the iframe omits allow-same-origin, preventing reviewed code from reaching the trusted parent DOM.

08 · Code review

Good, bad, ugly, questions

Good

Deep boundaries. Command, HTTP validation, file confinement, persistent state, and browser behavior are separated without framework scaffolding. All implementation files stay below 300 lines. The security model is explicit at the dangerous boundaries, and no third-party runtime dependency is introduced.

Bad

No real-browser automated E2E. test/review-artifact/server.test.ts exercises HTTP and streamed events, while classifier tests exercise geometry decisions, but pointer selection, iframe focus, actual postMessage behavior, and responsive rendering still rely on manual browser use.

Ugly

Two growth seams are uncapped. session-store.mjs retains full chat history and up to 200 warning keys indefinitely per artifact. Inputs are individually bounded, but a long-lived, heavily used session can grow the JSON state file without a total-history retention policy.

Question

When should history compact? The current behavior favors complete local durability. Before broad use, decide whether reopen should retain all conversation forever or compact acknowledged history after a size or age threshold.

09 · Decision log

Why the runtime has this shape

High confidence

Own the runtime instead of invoking an upstream package

The user explicitly chose a locally maintained implementation. The result uses only Node built-ins and keeps the review protocol inspectable in this repository.

High confidence

Keep the reviewed source untouched

Bridge and audit scripts are injected into the served response, not written into the artifact. This keeps review instrumentation out of canonical HTML while still allowing arbitrary semantic documents.

High confidence

Treat approval as data, not affirmative prose

approved and ended are separate terminal events with an actor. Browser close, poll interruption, and an agent-ended session do not masquerade as approval.

High confidence

Use an opaque-origin iframe

The parent shell performs network operations; reviewed content receives only scripts and forms. Cross-context messages validate event.source because an opaque sandbox cannot provide a useful same-origin string.

Inferred

Use JSON persistence rather than a local database

One serialized daemon and small per-path review sessions make atomic JSON sufficient today. A database would add migration and packaging surface without improving the current command contract.

10 · Re-entry

Things future-you must preserve

Key invariants

  • Canonical real path defines session identity.
  • Event take and removal must remain one atomic store mutation.
  • Only explicit approved clears a gate.
  • Artifact source must not be rewritten for instrumentation.

Non-obvious coupling

  • shell.js and bridge.js share literal postMessage event names across separate globals.
  • server.mjs SSE event types must match shell client handlers.
  • Session chat shape is serialized into shell.mjs bootstrap JSON.

Gotchas

  • Do not add allow-same-origin to the iframe.
  • Host validation and Origin validation defend different paths; retain both.
  • String-prefix path checks are insufficient; asset confinement depends on realpath plus path.relative.

Worth doing next

  • Add a fixture-driven real-browser E2E harness when this repository is ready to own that dependency.
  • Define a session-history retention limit before usage becomes high-volume.
  • Centralize browser event names only if the protocol grows enough to justify another module.
