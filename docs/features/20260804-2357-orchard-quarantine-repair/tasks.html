Vertical Slices

S1

Block the common harness branch switch

Close the exact incident path end to end without changing manual Git.

AFK · complete
DependenciesNone
Stories1, 5, 6
ModeAFK — deterministic guard behavior
Test surfaceShared policy evaluator and harness adapters
What to build. Add a mandatory branch-binding policy that receives caller location, blocks an unscoped git switch when the harness is inside Orchard, permits the same command in an ordinary checkout, and projects the decision through both harness adapters and the generated pi guard.
Acceptance criteria
  • An unscoped git switch from any directory beneath Orchard is blocked before execution with a branch-binding-specific refusal.
  • The same command from an ordinary checkout remains allowed by this policy.
  • Pi forwards its tool-call context directory and Claude forwards its hook payload directory into the shared policy input.
  • The policy registry pins violating and benign boundary examples and marks the guarantee mandatory for every harness.
  • Conformance proves both harnesses block the violating example, and the committed pi projection rebuilds without drift.
  • No terminal command interception, Git hook, or manual-Git restriction is introduced.
S2

Guard every recognizable branch-binding change

Resolve explicit targets accurately and avoid blocking file restoration.

AFK · complete
DependenciesS1
Stories2, 3, 4, 5
ModeAFK — parser boundary is specified
Test surfaceShared policy evaluator
What to build. Extend the guard to resolve unscoped, explicit Git-target, and literal directory-change contexts; recognize all agreed direct branch-binding mutations; allow explicit checkout path mode and restore; and guide cross-repository harness work toward an absolute Git target.
Acceptance criteria
  • Switch, branch-mode checkout, branch rename flags, symbolic HEAD reassignment, and direct HEAD update are blocked when their effective target is beneath Orchard.
  • Explicit checkout path mode, restore, help, and read-only Git commands remain allowed.
  • An explicit Git target outside Orchard is allowed even when the harness caller directory is managed.
  • An explicit Git target into Orchard is blocked from an ordinary caller directory.
  • Literal directory changes, relative paths, home-relative paths, command chains, and absolute Git executable names receive deterministic target resolution.
  • The refusal recommends explicit absolute Git scoping and does not claim to evaluate dynamic variables, aliases, scripts, or nested programs.
S3

Make durable quarantine visible and structured

Turn a hidden dead end into inspectable evidence without enabling repair yet.

AFK · complete
DependenciesNone
Stories7, 8, 9, 10
ModeAFK — additive state and output contract
Test surfaceBranch-binding verifier and spawned status command
What to build. Introduce reusable branch-binding inspection, record stable evidence for every quarantine cause, and render quarantined task worktrees in scoped and global human status while preserving the existing versioned machine envelope.
Acceptance criteria
  • A branch mismatch records a stable code, human reason, expected branch, observed branch or detached state, observed commit, and detection time.
  • Missing metadata, available-slot branch conflict, duplicate registration, and reconstructed role conflict receive distinct stable codes.
  • Human status shows quarantine intent, exact path, expected and observed branch state, reason, and detection time with distinct color and no-color presentation.
  • JSON status exposes structured evidence without requiring consumers to parse human reason text.
  • Restoring the expected branch and refreshing status leaves quarantine intact and visible.
  • Recovery inspection and state writes run under the project lock, and ordinary lifecycle commands continue excluding quarantined slots.
S4

Repair a proven branch binding explicitly

Deliver the complete happy path from discovery through audited metadata restoration.

AFK · complete
DependenciesS3
Stories10–13, 16, 20–24
ModeAFK — explicit command with fixed proof
Test surfaceRepair service and spawned Orchard command
What to build. Add the repair command, infer the quarantined slot from its exact worktree or require intent from the main project directory, validate the restored branch binding through shared Git metadata inspection, permit ordinary dirty work, atomically restore task lifecycle, retain an audit, and expose human, JSON, help, and completion behavior.
Acceptance criteria
  • Repair succeeds from the exact quarantined worktree without intent and from the main project directory with explicit intent.
  • A supplied intent inside the quarantined worktree must match that exact slot.
  • The assigned branch must be checked out at the registered canonical path and uniquely agree with Git worktree metadata.
  • Staged, unstaged, and untracked task changes are allowed and reported.
  • Success restores lifecycle task, clears active quarantine, and records the prior evidence plus repair time in lastRepair.
  • Human and JSON outcomes report the non-mutated accidental branch, dirty indicator, and verification evidence.
  • Snapshots prove repair changes no file, index entry, HEAD, ref, branch tip, or Git worktree metadata.
  • Top-level and command help describe repair safety, and completion lists only eligible branch-mismatch quarantine intents in the current project.
  • A second repair attempt fails unchanged because the slot is no longer quarantined.
S5

Keep ambiguous identity quarantined

Prove that repair cannot claim the wrong path, branch, project, or quarantine cause.

AFK · complete
DependenciesS4
Stories14, 15, 20
ModeAFK — fail-closed identity matrix
Test surfaceRepair service with real temporary repositories
What to build. Complete repair’s identity boundary so unsupported caller locations, unstructured or non-branch quarantine, wrong project or task role, missing metadata, and duplicate durable or Git registrations all fail without changing any durable or Git state.
Acceptance criteria
  • Repair is rejected from unrelated repositories and from linked worktrees other than the exact quarantined path.
  • Legacy unstructured quarantine and every structured non-branch quarantine code remain ineligible without parsing reason text.
  • The registered project, Git common directory, task-path role, and intent-path association must all agree.
  • Missing path metadata, wrong current branch, detached HEAD, duplicate path ownership, duplicate branch ownership, and duplicate durable registration each fail distinctly.
  • Canonical path aliases cannot make another worktree appear to be the registered slot.
  • Every failed identity check preserves quarantine, audit absence, owners, timestamps, files, refs, and Git worktree metadata exactly.
S6

Require stable Git state and non-conflicting ownership

Close the concurrency and operation-state gaps around an otherwise valid identity.

AFK · complete
DependenciesS4
Stories17–20, 23
ModeAFK — deterministic liveness and Git state
Test surfaceRepair service and concurrent command behavior
What to build. Refresh owner liveness under the project lock, permit zero or one live owner, reject conflicting owners and unresolved lifecycle recovery, detect every agreed in-progress Git operation, and preserve fail-closed atomic behavior under concurrent repair attempts.
Acceptance criteria
  • Dead ownership claims are discarded before eligibility is evaluated.
  • Repair succeeds with zero or one live owner and preserves the surviving owner claim.
  • Repair fails with multiple live owners and reports conflicting ownership without changing state.
  • Merge, rebase, cherry-pick, revert, and bisect state each block repair even when the expected branch is checked out.
  • Unresolved conversion or pending cleanup recovery blocks repair.
  • Concurrent repair attempts serialize under the project lock; at most one succeeds and the other observes the completed lifecycle without corrupting state.
  • Every operation-state or ownership failure preserves quarantine and all Git facts exactly.
