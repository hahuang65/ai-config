1 Problem statement

Pi currently loads all six advisory rules as a concatenated always-on instruction file (AGENTS.md), burning ~2,700 tokens every turn — including during grilling and task breakdown phases where no rule is relevant. And pi has no sub-agent capability, so the build pipeline's post-implementation review chain — which invokes specialized agents like code-reviewer, database-reviewer, and refactor-cleaner — cannot run in pi as it does in Claude Code and oh-my-pi. Without a fix, pi users either skip the review chain or run inline without isolation.

2 Solution

📄 Rule files at ~/.pi/agent/rules/ → 🔧 Subagent extension installed → 🔁 Review chain runs in pi

Change 1 — On-demand rules. Remove the generated AGENTS.md concatenation. Add rules to pi's consumed categories so individual files are symlinked. Skills tell the AI to read ~/.pi/agent/rules/ when entering a rules-relevant phase.

Change 2 — Subagent extension. Symlink pi's official subagent extension from /opt/pi-coding-agent/examples/extensions/subagent/. It registers a subagent tool callable with { agent, task } that spawns isolated pi sub-processes. Existing agent definitions at ~/.pi/agent/agents/ are auto-discovered.

3 User stories

  1. As a pi user, I want the six advisory rules to not consume context tokens when I'm not implementing code, so that I don't pay unnecessary per-turn API costs.
  2. As a pi user running the /build pipeline, I want the AI to explicitly load the advisory rules when entering the implement phase, so that my code still follows the project conventions.
  3. As a pi user running the /build pipeline, I want the review chain (code-reviewer, refactor-cleaner, database-reviewer, doc-updater) to work in pi the same way it works in Claude Code and oh-my-pi, so that I get the same quality gates.
  4. As an ai-config maintainer, I want the rules to still be authored once in rules/*.md and reach all three harnesses, so that there is one source of truth.
  5. As an ai-config maintainer, I want the test gate to validate the new pi layout, so that drift is caught in CI.

5 Implementation decisions

Decision 1 — Pi manifest

consumed_categories changes from (skills commands agents) to (skills commands agents rules). The generic install loop handles symlinking. The AGENTS.md symlink ln -sf "$MOD/advisory-rules.md" "$config_root/AGENTS.md" is removed from install_module.

The subagent extension is added: if /opt/pi-coding-agent/examples/extensions/subagent/ exists, symlink index.ts and agents.ts into $config_root/extensions/subagent/. Gracefully skips if pi isn't installed.

Decision 2 — Removed artifacts

scripts/gen-pi-agents.sh is deleted — the concatenation script has no other consumers. harnesses/pi/advisory-rules.md is deleted — it was the committed output of that script. The Makefile's rules target (which ran the script) is removed.

Decision 3 — Skill instructions

The 4 build-pipeline skills currently say: "In Claude Code these are global instructions; in oh-my-pi, load via rule://<name>." They gain: "in pi, read from ~/.pi/agent/rules/". The full line becomes:

"In Claude Code these are global instructions; in pi, read from ~/.pi/agent/rules/; in oh-my-pi, load via rule://<name> when entering the rule's domain."

Decision 4 — Agent instructions

7 agent files currently list ~/.claude/rules/ for Claude Code and ~/.omp/agent/rules/ for oh-my-pi. Each gains ~/.pi/agent/rules/ for pi. The line becomes:

"Read from rules/ in the repo root (or ~/.claude/rules/ for Claude Code, ~/.pi/agent/rules/ for pi, ~/.omp/agent/rules/ for oh-my-pi)."

Decision 5 — ADR 0014

A new ADR records the reversal: pi's advisory rules switch from always-on concatenation (ADR-0013) to on-demand via individual files. Documents the rationale (per-turn token cost, consistency with omp pattern) and the new subagent extension.

6 Testing decisions

What's tested

  • test_isolation — unchanged, no cross-harness pollution

What's removed
  • test_pi_agents_current — drift check for the deleted concatenation

Prior art: test_install_behavior already validates file layout after a throwaway install. The drift-check pattern (diff -q against regenerated output) is used by test_pi_bundle_current and remains unchanged.

7 Out of scope

  • Sub-agent support for oh-my-pi or Claude Code (they already have it via task and Task())
  • Sandboxing for pi sub-agents (the subagent extension uses the same filesystem)
  • A dedicated "build mode" that auto-loads rules only during build phases
  • Changes to the advisory rule content itself
  • New agent definitions beyond what already exists at agents/*.md
