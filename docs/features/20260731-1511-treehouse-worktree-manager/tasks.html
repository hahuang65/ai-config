Inspect Treehouse projects from the CLI

AFKComplete
Repository: Git dotfiles
Blocked by: None
Stories: 4, 16–18, 37–38

T02

Acquire an offline task worktree safely

AFKComplete
Repository: Git dotfiles
Blocked by: T01
Stories: 5–6, 10, 15, 21–22, 34

Test surface

First RED through black-box treehouse new --offline; direct project-registry tests for naming, capacity, atomic state, and lock contention.

What to build

Create project groups, normalize intents, allocate a slot from local trunk, attach an ordinary named branch, and return human, path-only, or JSON outcomes. Enforce the total active-plus-available capacity and serialize mutation through a filesystem lock.

Acceptance criteria

  • Complete: Offline acquisition creates a task worktree on a named branch without network access.
  • Complete: Existing basename ownership remains stable and only a newly colliding project is parent-qualified.
  • Complete: Capacity defaults to four, rejects invalid environment values, and never evicts work.
  • Complete: Path and JSON modes do not open a shell and expose a stable structured outcome.
  • Complete: Concurrent acquisition cannot allocate the same slot or corrupt durable state.

T14

Continue Treehouse workflows in pi

HITLComplete
Repository: AI dotfiles
Blocked by: T06, T10, T11
Stories: 2, 13–14, 26–27, 38
HITL reason: the automated extension contract is testable, but final acceptance requires observing the prefilled one-Enter confirmation, same-window pi session replacement, and return in a real TUI.

Test surface

First RED through a fake pi Extension API exercising editor preservation, authenticated command prefill, one-time token handling, and the registered command; targeted integration through pi’s documented session manager and one human smoke check.

What to build

In the AI dotfiles repository, install a user-level pi adapter that invokes the independently installed Treehouse CLI in machine mode, validates its protocol version, records ownership, requires an empty editor, stores a one-time authenticated transition, preloads its internal command, and terminates the initiating tool turn. One user Enter executes the privileged command context, forks the persisted conversation into the target cwd, switches the same TUI, and resumes the requesting workflow without another model turn. Refuse to overwrite editor drafts, reject token replay, release ownership on ordinary session shutdown, and preserve work when confirmation is declined or transition fails.

Acceptance criteria

  • Complete: The tool preloads one authenticated internal transition command into an empty editor and prevents an extra pre-transition model turn.
  • Complete: The replacement session preserves conversation context and rebuilds cwd-bound tools, instructions, resources, and trust.
  • Complete: Editor-draft refusal, declined confirmation, missing persistence, token replay, switch failure, and ordinary shutdown leave the task worktree intact with accurate ownership.
  • Complete: Default merge returns the same visible pi interaction to the main project directory before cleanup.
  • Complete: A human verified prefilled one-Enter entry and return in a real pi TUI without typing command text or starting another visible agent or terminal.
T15

Delegate build isolation and transitions through Treehouse

HITLComplete
Repository: AI dotfiles
Blocked by: T06, T10, T11
Stories: 1–3, 13–14, 26–27, 38–39
HITL reason: final acceptance requires observing Claude Code enter and return from a registered external worktree while retaining the current conversation.

Test surface

First RED through the shared workflow-content contract and fake available, missing, incompatible, and post-acquisition Treehouse outcomes, followed by one real Claude Code native-worktree smoke check.

What to build

In the AI dotfiles repository, deliver the Treehouse skill as the workflow owner that delegates acquisition, conversion, entry, and return to the installed lifecycle CLI before generic continuation. Update build to continue inside any existing linked worktree, preflight the CLI outside one, and otherwise delegate without altering its four gates. Missing or incompatible CLI preflight may offer an explicit ordinary local-branch fallback with clear loss of Treehouse merge support. Route Claude entry through EnterWorktree, return through ExitWorktree with keep behavior before CLI cleanup, and fail safely when either native operation is unavailable.

Acceptance criteria

  • Complete: Build started in an unmanaged linked worktree continues without Treehouse adoption or relocation.
  • Complete: Build started outside a linked worktree delegates the branch-state choice, acquisition, and transition to Treehouse.
  • Complete: Treehouse contains no build-phase knowledge and resumes callers with a generic continuation.
  • Complete: Native transition failure reports the safe task path without launching another agent or creating a handoff artifact.
  • Complete: A human verified Claude entry through EnterWorktree and default merge return through ExitWorktree with keep behavior in the same visible conversation.
  • Complete: Missing or incompatible CLI preflight stops standalone Treehouse workflows, while build alone may warn and request explicit approval for a non-Treehouse local task branch.
